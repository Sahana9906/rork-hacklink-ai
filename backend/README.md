# HackLink AI backend

Java 21 + Spring Boot REST backend for the HackLink AI Android application. The backend owns authentication, evidence-backed developer profiles, hackathon matching, complementary team formation, invitations, internships, connections, notifications, and safe public QR profiles.

## Architecture

```text
Android / Retrofit
        |
        v
Controller -> Service -> Repository -> PostgreSQL
                 |
                 +-> Integration abstractions (GitHub, LinkedIn, Gemini, PDFBox)
```

Controllers only validate input and delegate. Domain decisions live in services. The invitation acceptance and finalization paths are transactional and use pessimistic team/invitation locks plus database uniqueness constraints.

## PostgreSQL configuration

Create a local database and user:

```sql
CREATE USER hacklink WITH PASSWORD 'change-me';
CREATE DATABASE hacklink OWNER hacklink;
```

Flyway creates the complete schema on first start. Hibernate is set to `ddl-auto: validate`, so schema changes must be added as a new migration rather than silently generated by Hibernate.

## Run

Prerequisites: Java 21 and PostgreSQL.

From the backend directory:

```bash
./gradlew bootRun
```

From the repository root, the same delegated wrapper can be called as:

```bash
./backend/gradlew -p backend bootRun
```

The API listens on `http://localhost:8080`. Set `DATABASE_*` variables first. If using the Android emulator, use `http://10.0.2.2:8080` as the base URL; a physical device needs the host machine's LAN IP and firewall access.

## REST API

All protected endpoints require `Authorization: Bearer <accessToken>`.

### Authentication and profile

- `POST /api/auth/register` — create a user and initial profile; returns JWT (`201`)
- `POST /api/auth/login` — authenticate with email/password; returns JWT (`200`)
- `GET /api/auth/me` — return the authenticated profile
- `GET /api/profile` — private profile
- `PATCH /api/profile` — update profile fields and discoverability
- `POST /api/profile/skills` — add or update a manual skill with manual evidence
- `POST /api/profile/projects` — add a manual project
- `POST /api/profile/resume` — multipart PDF upload and evidence-backed extraction
- `GET /api/profile/resume` — latest resume metadata and extracted skills

### Authorized integrations

- `POST /api/integrations/github/connect` — connect an authorized GitHub account; token is encrypted server-side
- `GET /api/integrations/github` — connected account metadata
- `POST /api/integrations/github/sync` — fetch authorized repositories from GitHub API, create project/skill evidence
- `DELETE /api/integrations/github` — disconnect and delete stored GitHub token
- `POST /api/integrations/linkedin/connect` — store only permitted LinkedIn subject/scope data
- `DELETE /api/integrations/linkedin` — revoke the local LinkedIn connection/consent

The backend never scrapes GitHub or LinkedIn. LinkedIn fields represent only the product/API-approved data that the user authorized.

### Hackathons

- `GET /api/hackathons`
- `GET /api/hackathons/{id}`
- `GET /api/hackathons/{id}/skills`
- `GET /api/hackathons/{id}/match` — deterministic score, matched skills, gaps, reasons
- `POST /api/hackathons/{id}/register`

### Teams and invitations

- `POST /api/teams` — owner must be registered for the hackathon
- `GET /api/teams` — teams owned by the user
- `GET /api/teams/{id}`
- `GET /api/teams/{id}/skill-coverage`
- `GET /api/teams/{id}/recommendations` — discoverable users ranked by missing-capability complementarity
- `POST /api/teams/{id}/invitations`
- `POST /api/teams/{id}/finalize`
- `DELETE /api/teams/{id}/members/me`
- `DELETE /api/teams/{id}/members/{userId}` — owner only
- `GET /api/invitations` — pending invitations for current user
- `POST /api/invitations/{id}/accept`
- `POST /api/invitations/{id}/reject`
- `DELETE /api/invitations/{id}` — sender cancels a pending invitation

Acceptance locks the invitation and team, checks expiration, ownership, current capacity, duplicate membership, and incompatible same-hackathon membership, then atomically inserts an accepted member, updates invitation status, and creates a notification.

Finalization checks owner authorization, minimum/maximum size, required skill coverage, no pending invitations, accepted member status, and hackathon registration before changing `RECRUITING`/`FULL` to `SUBMITTED`.

### Internships

- `GET /api/internships`
- `GET /api/internships/{id}`
- `GET /api/internships/{id}/match`
- `POST /api/internships/{id}/save`
- `DELETE /api/internships/{id}/save`
- `POST /api/internships/{id}/apply`

The apply response contains the external application URL and `externalSubmissionConfirmed: false`. The backend records tracking state only; it does not claim that a company application was submitted.

### Connections and notifications

- `POST /api/connections/{userId}`
- `POST /api/connections/{id}/accept`
- `POST /api/connections/{id}/reject`
- `DELETE /api/connections/{id}`
- `GET /api/notifications`
- `POST /api/notifications/{id}/read`
- `POST /api/notifications/read-all`

### QR networking

- `GET /api/public/profiles/{publicProfileId}` — unauthenticated safe public profile

The QR payload should be `hacklink://profile/{publicProfileId}`. It contains no password, JWT, OAuth token, email, or private profile data.

## Sample requests

Register:

```bash
curl -X POST http://localhost:8080/api/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"email":"sahana@example.com","password":"correct-horse-battery","fullName":"Sahana B"}'
```

Update profile:

```bash
curl -X PATCH http://localhost:8080/api/profile \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"headline":"Backend developer building useful AI tools","role":"Backend Developer","experienceLevel":"INTERMEDIATE","availability":"Weekends","discoverable":true}'
```

Upload a resume:

```bash
curl -X POST http://localhost:8080/api/profile/resume \
  -H "Authorization: Bearer $TOKEN" \
  -F 'file=@./resume.pdf;type=application/pdf'
```

Register for the seeded Google GenAI Hackathon:

```bash
curl -X POST http://localhost:8080/api/hackathons/10000000-0000-0000-0000-000000000001/register \
  -H "Authorization: Bearer $TOKEN"
```

Create a team, invite a complementary teammate, then finalize:

```bash
curl -X POST http://localhost:8080/api/teams \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"name":"GenAI Innovators","hackathonId":"10000000-0000-0000-0000-000000000001"}'

curl -X POST http://localhost:8080/api/teams/{teamId}/invitations \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"receiverId":"{ananyaUserId}","message":"Your React experience fills our frontend gap."}'

curl -X POST http://localhost:8080/api/invitations/{invitationId}/accept \
  -H "Authorization: Bearer $ANANYA_TOKEN"

curl -X POST http://localhost:8080/api/teams/{teamId}/finalize \
  -H "Authorization: Bearer $TOKEN"
```

Error responses are consistent:

```json
{
  "code": "TEAM_FULL",
  "message": "This team has reached its maximum size.",
  "timestamp": "2026-08-09T12:00:00Z",
  "path": "/api/invitations/{id}/accept"
}
```

## Retrofit client shape

The current Android prototype is mock-data driven. When switching to the backend, create a Retrofit service with the same paths and attach the JWT through an OkHttp interceptor. Example shape:

```kotlin
interface HackLinkApi {
    @POST("api/auth/register")
    suspend fun register(@Body request: RegisterRequest): AuthResponse

    @POST("api/auth/login")
    suspend fun login(@Body request: LoginRequest): AuthResponse

    @GET("api/auth/me")
    suspend fun me(): ProfileResponse

    @GET("api/hackathons")
    suspend fun hackathons(): List<HackathonResponse>

    @GET("api/hackathons/{id}/match")
    suspend fun hackathonMatch(@Path("id") id: UUID): HackathonMatchResponse

    @POST("api/hackathons/{id}/register")
    suspend fun registerForHackathon(@Path("id") id: UUID): HackathonResponse

    @POST("api/teams")
    suspend fun createTeam(@Body request: CreateTeamRequest): TeamResponse

    @GET("api/teams/{id}/skill-coverage")
    suspend fun skillCoverage(@Path("id") id: UUID): SkillCoverageResponse

    @GET("api/teams/{id}/recommendations")
    suspend fun recommendations(@Path("id") id: UUID): List<TeamMatchResponse>

    @POST("api/teams/{id}/invitations")
    suspend fun invite(@Path("id") id: UUID, @Body request: InvitationRequest): InvitationResponse

    @POST("api/invitations/{id}/accept")
    suspend fun acceptInvitation(@Path("id") id: UUID): TeamResponse

    @POST("api/invitations/{id}/reject")
    suspend fun rejectInvitation(@Path("id") id: UUID): InvitationResponse

    @POST("api/teams/{id}/finalize")
    suspend fun finalizeTeam(@Path("id") id: UUID): TeamResponse

    @GET("api/internships")
    suspend fun internships(): List<InternshipResponse>

    @GET("api/internships/{id}/match")
    suspend fun internshipMatch(@Path("id") id: UUID): InternshipMatchResponse

    @POST("api/internships/{id}/save")
    suspend fun saveInternship(@Path("id") id: UUID): InternshipResponse

    @POST("api/internships/{id}/apply")
    suspend fun apply(@Path("id") id: UUID): ApplicationResponse

    @GET("api/notifications")
    suspend fun notifications(): List<NotificationResponse>
}
```

Use an OkHttp interceptor to read the token from secure Android storage and add `Authorization`. Do not log the token or error bodies containing credentials. Map HTTP `409` to a user-facing conflict message, `422` to validation feedback, and `401` to a session-expired flow.
